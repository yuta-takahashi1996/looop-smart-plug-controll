# 安全設計・例外処理

## 14.1 基本方針

節電よりも安全な電源供給と制御の確実性を優先する。

## 14.2 異常時の処理

| 発生事象 | 対応 |
|---|---|
| 予報取得失敗 | 新規自動OFFを禁止 |
| 料金データ欠損 | 対象データを使用しない |
| SwitchBot認証エラー | 制御停止・異常表示 |
| SwitchBot通信エラー | 再試行・異常表示 |
| 操作後の状態不一致 | 成功扱いしない |
| スケジュール失効 | ONへの復帰を要求 |
| 無効なスケジュール | 実行しない（プラグ ON のまま） |
| システム再起動 | 現在状態を取得・再初期化 |
| 運用終了 | ONへの復帰を要求（有効なでんき警報のスケジュール中を除く。終了時にONへ復帰） |
| 手動モード | 通常の自動制御を停止 |
| ポータブル電源の残量が下限以下 | ONへの復帰を要求（でんき警報のスケジュール中を含む）。新規のOFFを開始しない |
| ポータブル電源の残量を取得できない | 残量による制御を行わず、OFF時間の制限で保護する・異常表示 |

でんき警報のスケジュールは、OFF時間の制限（運用時間・最大連続OFF時間・1日の最大OFF時間）を超えて実行する（docs/07-control-logic.md §7.5）。蓄電池切れで給電が止まらないよう、ポータブル電源の残量が `BATTERY_MIN_PERCENT`（初期値 5%）以下になった時点で ON に戻す（docs/07-control-logic.md §7.7）。残量を取得できない間は蓄電池切れの可能性があるため、画面に警報のスケジュールであることを明示し、ユーザーが個別に無効にできるようにする。

## 14.3 Dry Run

Dry Runでは実際のSwitchBot操作を実行しない。

- 実行予定の操作を記録する。
- 予定時刻を保存する。
- 想定制御状態を表示する。
- 推定節約額を算出する。

Dry Runを解除する際はWeb UI上で確認操作を必要とする。

## 14.4 独立した復旧策

ホスト停止や通信障害では、アプリケーションからON操作を実行できない可能性がある。

そのため、本番運用前にスマートプラグ側のスケジュール機能など、制御プログラムに依存しない安全復帰策を検討する。
