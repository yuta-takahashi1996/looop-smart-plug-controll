# 安全設計・例外処理

## 14.1 基本方針

節電よりも安全な電源供給と制御の確実性を優先する。

## 14.2 異常時の処理

| 発生事象 | 対応 |
|---|---|
| 予報取得失敗 | 新規自動OFFを禁止 |
| 料金データ欠損 | 対象データを使用しない |
| SwitchBot認証エラー | 制御停止・異常表示 |
| SwitchBot通信エラー | 再試行・異常表示 |
| 操作後の状態不一致 | 成功扱いしない（1回送り直し、失敗は異常表示。同じ要求は5分間繰り返さない）。機器ごとに判定し、他の機器の制御は続ける |
| プラグの状態が不明 | ON への初期化のみ要求し、OFF は要求しない |
| スケジュール失効 | ONへの復帰を要求 |
| 無効なスケジュール | 実行しない（プラグ ON のまま） |
| 任意 OFF のスケジュール | でんき注意報と同じ OFF 時間の制限・残量の下限を適用する（予報の取得失敗時もユーザーの指定として実行する） |
| システム再起動 | 現在状態を取得して引き継ぐ（ON・OFF はスケジュールに従って次の制御サイクルで判断）。取得できない場合のみ ON へ初期化 |
| システムの終了 | プラグを操作しない（OFF のまま停止しうる。停止中は残量を監視しないため、§14.4 の独立した復旧策で ON に戻す） |
| 運用終了 | ONへの復帰を要求（残量を取得できている間の、有効なでんき警報のスケジュール中を除く。警報の終了時にONへ復帰） |
| 手動モード | 通常の自動制御を停止 |
| ポータブル電源の残量が下限以下、または次の取得までに下限を下回る予測 | そのポータブル電源に紐づくプラグだけ ONへの復帰を要求（でんき警報のスケジュール中を含む）し、そのスケジュールの終了まで OFF にしない。スケジュールは中断せず、他の対象機器は続ける（docs/07 §7.7） |
| 紐づくポータブル電源がない制御機器 | 残量を取得できない場合と同じく、OFF時間の制限で保護する |
| 充電モードを変更できない・照合できない | 成功扱いにしない・異常表示。プラグの制御は継続し、自動の変更は5分ごとに再試行する |
| ポータブル電源の残量を取得できない | 残量による制御を行わず、OFF時間の制限で保護する（でんき警報のスケジュールにも適用）・異常表示 |

でんき警報のスケジュールは、ポータブル電源の残量を取得できる間に限り、OFF時間の制限（運用時間・最大連続OFF時間・1日の最大OFF時間）を超えて実行する（docs/07-control-logic.md §7.5）。蓄電池切れで給電が止まらないよう、OFF 中は5分ごとに残量と消費電力を取得し、残量が `BATTERY_MIN_PERCENT`（初期値 5%）を下回る前に ON に戻す（docs/07-control-logic.md §7.7）。残量を取得できない間は、警報のスケジュールにも OFF 時間の制限を適用する。

## 14.3 Dry Run

Dry Runでは実際のSwitchBot操作を実行しない。

- 実行予定の操作を記録する。
- 予定時刻を保存する。
- 想定制御状態を表示する。
- 推定節約額を算出する。

Dry Runを解除する際はWeb UI上で確認操作を必要とする。

Dry Run 中も制御サイクル（docs/07-control-logic.md §7.8）・実行時の安全判定・残量の取得・起動時の状態の引き継ぎは通常どおり動作し、SwitchBot へのコマンド送信と Jackery の充電モードの変更だけを行わない。制御履歴には結果 `DRY_RUN`（確認結果なし）として記録し、画面では「想定の状態」と Dry Run の推定値であることを明示する。

実制御は以下の両方を満たす場合のみ行う。

1. 環境変数 `DRY_RUN=false`（かつ SwitchBot の認証情報が設定済み）で起動している。
2. 設定画面で「実制御を開始」と入力して確認操作を行った（DB に保持し、再起動後も引き継ぐ）。

Dry Run へはいつでも設定画面から戻せる。切り替え時は想定状態を破棄し、次のサイクルで実機の状態から初期化し直す。画面のヘッダーには Dry Run／実制御中を常に表示する。

## 14.4 独立した復旧策

ホスト停止や通信障害では、アプリケーションからON操作を実行できない可能性がある。また、正常終了時もプラグを ON に戻さない（docs/09-scheduling.md §9.3）ため、OFF 中に停止したまま再起動しない場合はプラグが OFF のまま残る。

そのため、本番運用前にスマートプラグ側のスケジュール機能など、制御プログラムに依存しない安全復帰策を検討する。

例：SwitchBot アプリで制御対象のすべてのプラグに「毎日 運用終了時刻の少し後に ON」のスケジュールを設定しておく（制御対象を追加したときも設定する）。アプリやホストが停止して OFF のまま残っても、その時刻には ON に戻る。
