# スケジューリング設計

## 9.1 運用例

| 時刻 | 処理 |
|---|---|
| 常時 | システムは常時稼働し、毎分の制御サイクルでスケジュールを実行する |
| 16:15 | 翌日予報取得 |
| 自動 OFF の許可終了時刻 | スマートプラグON（終日許可の場合は行わない。残量を取得できている間の、有効なでんき警報のスケジュール中を除く） |

自動 OFF を許可する時間帯はWeb UIの設定画面から変更可能とする（docs/07-control-logic.md §7.5）。

## 9.2 起動時

- 設定読み込み
- DB接続確認
- SwitchBot API接続確認
- プラグ状態確認
- プラグ状態の引き継ぎ（取得できない場合のみ安全側への初期化）
- 当日予報取得
- スケジュール生成
- 自動制御開始

起動時は、当日の残り時間を対象として計画を再生成する。

起動時は制御機器ごとに状態を取得し、取得できればその状態を引き継いで操作しない（以下、機器ごとに扱う。docs/17 §17.7.4）。ON・OFF は次の制御サイクルがスケジュールに従って判断する（実行中の OFF のスケジュールの途中で再起動しても ON に戻さない。有効なスケジュールがなく OFF だった場合は、最初の制御サイクルで ON に戻し、理由を「起動時に OFF だったため ON に戻す」として記録する）。MANUAL モードで OFF だった場合、手動 OFF の継続時間は起動時から数える。

状態を取得できない場合（通信エラー、SwitchBot が未設定）のみ安全側への初期化として ON を要求し、制御履歴に SAFETY として記録する。初期化に失敗しても Web UI は起動し（制御状態は SAFE のまま）、次の制御サイクルで初期化をやり直す。

## 9.2.1 定期実行

| 処理 | タイミング |
|---|---|
| 制御サイクル（スケジュールの実行） | 毎分（5秒） |
| 料金予報の取得とスケジュールの再生成 | 起動時、毎日16:15、未取得の間は15分ごと |
| 任意スケジュールの展開（当日・翌日分） | 起動時、毎日16:15（予報の取得結果によらない）、ルールの保存時・再生成時 |
| 制御機器の状態の確認（機器ごと） | 5分ごと |
| 単価に関わるお知らせの確認 | 起動時、毎日9:30 |
| 日次集計（前日分） | 毎日0:05、起動時（直近の未集計分も） |
| バックアップ・古いデータの削除 | 毎日3:30 |

## 9.3 終了時

終了時はプラグ・充電モードを操作しない（ON へ復帰させない）。実行中のスケジュールも実行中のまま残し、再起動後は状態を引き継いで続きから実行する（§9.2）。再ビルド・再起動のたびにプラグが ON→OFF と切り替わるのを避けるため。

停止中にスケジュールが終了していれば、再起動後の制御サイクルで終了として扱い、ON に戻す・終了時の充電モードに切り替える。

停止したまま再起動しない場合、プラグは停止時の状態（OFF を含む）のまま残り、残量の監視も行われない。強制終了・通信障害・ホスト停止の場合と同じく、制御プログラムに依存しない安全復帰策（docs/14-safety.md §14.4）で ON に戻す。
