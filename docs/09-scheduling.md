# スケジューリング設計

## 9.1 運用例

| 時刻 | 処理 |
|---|---|
| 08:50 | システム起動 |
| 08:51 | 初期化・状態確認 |
| 08:52 | 当日予報取得 |
| 08:53 | 制御計画生成 |
| 09:00 | 自動制御開始 |
| 運用時間中 | 料金予報に基づく制御 |
| 16:15 | 翌日予報取得 |
| 18:00 | スマートプラグON |
| 18:05 | 履歴保存・終了処理 |

時刻はWeb UIの設定画面から変更可能とする。

## 9.2 起動時

- 設定読み込み
- DB接続確認
- SwitchBot API接続確認
- プラグ状態確認
- 安全側への初期化
- 当日予報取得
- スケジュール生成
- 自動制御開始

運用開始時刻を過ぎてから起動した場合も、残り時間を対象として計画を再生成する。

安全側への初期化では ON を要求し、制御履歴に SAFETY として記録する。初期化に失敗しても Web UI は起動し（制御状態は SAFE のまま）、次の制御サイクルで初期化をやり直す。

## 9.2.1 定期実行

| 処理 | タイミング |
|---|---|
| 制御サイクル（スケジュールの実行） | 毎分（5秒） |
| 料金予報の取得とスケジュールの再生成 | 起動時、毎日16:15、未取得の間は15分ごと |
| 任意スケジュールの展開（当日・翌日分） | 起動時、毎日16:15（予報の取得結果によらない）、ルールの保存時・再生成時 |
| プラグ状態の確認 | 5分ごと |
| 単価に関わるお知らせの確認 | 起動時、毎日9:30 |
| 日次集計（前日分） | 毎日0:05、起動時（直近の未集計分も） |
| バックアップ・古いデータの削除 | 毎日3:30 |

## 9.3 終了時

原則として、スマートプラグをONへ復帰させてから終了する。実行中のスケジュールは「中断（システムの終了）」として記録する。

ただし強制終了・通信障害・ホスト停止では終了処理を保証できないため、制御プログラムに依存しない安全復帰策も検討する。
