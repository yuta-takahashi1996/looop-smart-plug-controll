# Web UI設計

## 5.1 設計方針

PC・スマートフォンの双方から操作可能なレスポンシブUIを実装する。

- ダークモードを基本とする。
- 現在の電力単価と制御状態をトップページへ集約する。
- グラフを利用して料金変動を直感的に把握できるようにする。
- 自動制御と手動制御の状態を明確に区別する。
- 操作結果と実際に確認できた機器状態を区別して表示する。

## 5.2 画面一覧

| 画面 | パス | 主な機能 |
|---|---|---|
| ダッシュボード | `/` | 現在単価・料金グラフ（今日・明日）・制御状態・次回予定・手動操作 |
| 運転スケジュール | `/schedule` | 自動生成された制御予定・任意スケジュールの登録 |
| 制御履歴 | `/history` | 操作履歴・推定節約額 |
| 設定 | `/settings` | 制御条件・運用時間の変更 |

## 5.3 ダッシュボード

以下の情報を表示する。

**電力情報**

- 現在の電源単価（請求単価表示に切り替えた場合は請求単価と加算額の内訳）
- 現在の推定実効単価
- 現在・次のでんき予報の区分（でんき日和・注意報・警報）
- 次の30分コマの料金
- 当日の最高・最低単価
- 予報の最終取得日時

**制御情報**

- 自動制御の有効・無効
- スマートプラグの現在状態
- ポータブル電源の残量（%）・消費電力（W）と取得日時、OFF 中は下限に達する見込み時刻（参考：入力電力、残り給電時間）
- プラグの状態・ポータブル電源の状態を今すぐ取得するボタン（読み取りのみ）
- ポータブル電源の充電モード（高速充電／静かな充電）と変更ボタン（docs/07-control-logic.md §7.10。Dry Run では想定のモード）
- 次回切り替え予定
- 最終操作結果
- システムの稼働状態

**集計情報**

- 本日の推定節約額
- 今月の推定節約額
- 本日の電源切り替え回数
- 本日のOFF累計時間

料金グラフ（§5.4）も表示する。電力情報・制御情報・集計情報は60秒ごとに部分更新し、料金グラフは再描画を避けるため部分更新の対象外とする。

## 5.4 料金グラフ（ダッシュボード）

Chart.jsで30分単位の料金推移を表示する。独立した電力予報画面は設けず、ダッシュボードに統合する（以前の `/forecast` はダッシュボードへ転送する）。

- 今日・明日の切り替え表示（`/?day=tomorrow`）
- 現在時刻の表示
- 料金単価の推移（電源単価／請求単価の表示切り替え）
- でんき予報の区分（でんき日和・注意報・警報）の背景色表示
- ON/OFF予定時間帯の可視化
- 最高・最低・平均単価、注意報・警報の合計時間
- 最終取得日時
- データ取得エラーの表示

注意報・警報のコマの一覧は、グラフの背景色と運転スケジュール画面で確認できるため表示しない。加算額の内訳は設定画面で確認する。

## 5.4.1 単価の表示切り替え

Looopでんき公式アプリと同様に、単価を「電源単価」「請求単価」で切り替えて表示できるようにする（ダッシュボードの電力情報と料金グラフ）。

- 既定は電源単価。選択はログインセッションごとに保持する。
- 請求単価は電源単価＋加算額（docs/06-forecast-provider.md §6.5）で、実際の支払単価の目安として表示する。
- 制御の判断は表示の切り替えにかかわらず電源単価で行う。

## 5.5 運転スケジュール画面

でんき予報の注意報・警報から生成した OFF スケジュール（docs/07-control-logic.md §7.4）を時系列で表示し、操作できるようにする。

| 時刻 | 区分 | 電源単価（平均） | 状態 | 操作 |
|---|---|---:|---|---|
| 16:00〜18:00 | でんき注意報 | 43円 | 無効 | 有効にする・時間変更 |
| 19:00〜20:00 | でんき警報 | 120円 | 有効 | 無効にする・時間変更 |

※数値は表示例。

- 各スケジュールには、区分、有効・無効、自動／手動のどちらで有効化されたか、手動変更の有無、推定節約額を表示する。
- 有効・無効を個別に切り替えられる。
- 開始・終了時刻を30分単位で変更できる（他のスケジュールと矛盾しない範囲、docs/07-control-logic.md §7.6）。
- 開始時・終了時の充電モード（静かな充電／高速充電／変更しない）を表示し、個別に変更できる（開始時は開始前、終了時は終了前まで。docs/07-control-logic.md §7.10）。
- 有効なスケジュールのみ実行する。
- 今日・明日を切り替えて表示し、「再生成」で最新の予報から作り直せる（手動で変更したものは残る）。
- スマートフォンではカード形式で表示する。
- 任意スケジュールから展開したものは、区分を「任意（OFF）」「任意（ON）」とし、ルール名を表示する。

### 任意スケジュール

同じ画面で任意スケジュールのルール（docs/07-control-logic.md §7.9）を登録・管理する。

| 名前 | 内容 | 繰り返し | 時刻 | 状態 | 操作 |
|---|---|---|---|---|---|
| 夕方の在宅時間 | ON | 平日（月〜金） | 17:00〜19:00 | 有効 | 編集・無効にする・削除 |
| 昼の OFF | OFF | 毎日 | 12:00〜13:00 | 有効 | 編集・無効にする・削除 |

※表示例。

- 「追加」から名前・内容（ON／OFF）・時間帯（30分単位）・繰り返し（1回のみ＋対象日／毎日／曜日指定）・開始時と終了時の充電モード（初期値は設定画面の既定値）を入力して登録する。
- 検証に通らない場合（重なり・OFF 時間の制限の超過など）は、理由を表示して保存しない。
- 当日・翌日の開始済みのスケジュールや手動変更済みのスケジュールと重なり、その日に展開しなかった場合は、保存後に重なる日と時間帯を表示する。
- 削除には確認ダイアログを表示する。
- 1回のみのルールで対象日を過ぎたものは一覧に表示しない。

## 5.6 制御履歴画面

以下を確認できるようにする。

- 操作日時
- 操作元（AUTO / MANUAL / SAFETY）
- 操作前状態
- 要求状態
- 操作後の確認結果
- 制御理由
- エラー情報

日付による絞り込みに対応する。Dry Run の記録は「Dry Run」と表示し、実行するはずだった操作であることを明示する。

あわせて、月別の実績（日次集計、docs/10 §10.7）を表示する：日ごとの OFF 時間・切り替え回数・完了／中断／未実行の件数・推定節約額・残量の減少・実測の平均消費電力・失敗件数と、月の合計。

## 5.7 設定画面

初期リリースから制御条件をWeb UIで編集できるようにする。

主な設定項目：

| 設定 | 初期値 |
|---|---:|
| 運用開始時刻 | 09:00 |
| 運用終了時刻 | 18:00 |
| 注意報スケジュールの自動適用（AUTO_ENABLE） | 無効 |
| ポータブル電源の残量の下限（BATTERY_MIN_PERCENT） | 5% |
| ポータブル電源の容量（BATTERY_CAPACITY_WH） | 1070Wh |
| ポータブル電源の変換効率（推定節約額の計算・残量の予測に共用） | 85% |
| 最大連続OFF時間 | 120分 |
| 1日の最大OFF時間 | 180分 |
| 最低切り替え間隔 | 30分 |
| 想定平均負荷 | 150W |
| 充電モードの既定値（でんき予報のスケジュールの開始時・終了時） | 静かな充電・高速充電 |
| Dry Run | 有効 |

初期値はすべて仮設定とし、運用状況に応じて変更可能とする。

設定項目は「スケジュール」「充電モード」「運用時間」「OFF 時間の制限」「ポータブル電源」「推定節約額」に分けて、それぞれに説明を表示する。想定平均負荷と変換効率には、直近30日の OFF の実測（平均消費電力、残量減少と消費電力から推定した効率）を調整の目安として表示する。

請求単価の加算額（サービス料金・託送従量料金相当額・再エネ賦課金・補助金など）も、適用期間付きで設定画面から登録・削除できるようにする（docs/06-forecast-provider.md §6.5）。

## 5.8 手動操作

ダッシュボードから以下を操作できるようにする。

1. 自動制御開始
2. 自動制御停止
3. スマートプラグON
4. スマートプラグOFF
5. スケジュール再生成
6. 料金予報の再取得
7. ポータブル電源の充電モード変更（高速充電／静かな充電。制御情報の欄に表示）

手動操作を行った場合はMANUALモードへ移行し、通常の自動制御が手動操作を上書きしないようにする。

安全制御はMANUALモード中も有効とする。

- 「プラグON／OFF」「自動制御停止」で MANUAL へ移行し、実行中のスケジュールは「中断（手動操作／自動制御の停止）」とする。「自動制御停止」はプラグの状態を変えない。
- 「自動制御開始」で AUTO に戻り、次の制御サイクルからスケジュールに従う。
- MANUAL／AUTO は DB に保持し、再起動後も引き継ぐ（起動時の ON への初期化は行う）。
- 手動 OFF の安全制御：残量と予測で下限を下回る前に ON に戻す。残量を取得できない間は、最大連続OFF時間で ON に戻す（運用時間・1日の最大OFF時間は手動操作を優先して適用しない）。残量が下限以下のときは手動 OFF を受け付けない。
- プラグの操作には確認ダイアログを表示する。
- 充電モードの変更は MANUAL への移行を伴わない。確認ダイアログを表示する。超急速充電は扱わない。

## 5.9 データ更新

HTMXによる定期的な部分更新を採用する。

| データ | 更新方式 |
|---|---|
| 現在単価 | 30～60秒ごとに表示更新 |
| プラグ状態 | 保存済み状態を定期表示 |
| 制御スケジュール | 計画更新時 |
| 推定節約額 | 定期更新 |
| 料金グラフ | 予報更新時 |
| システムエラー | 定期更新 |

画面更新のたびにSwitchBot APIを直接呼び出す構成は避ける。

## 5.10 セキュリティ

- 初期リリースでは宅内LANからのアクセスに限定する。
- インターネットへ直接公開しない。
- Web UIには認証を実装する。
- 状態変更リクエストにはCSRF対策を設ける。
- SwitchBotの認証情報はブラウザへ送信しない。
- 手動操作は履歴に記録する。
- 接続元の制限を適用できる構成とする。
