# Web UI設計

## 5.1 設計方針

PC・スマートフォンの双方から操作可能なレスポンシブUIを実装する。

- ダークモードを基本とする。
- 現在の電力単価と制御状態をトップページへ集約する。
- グラフを利用して料金変動を直感的に把握できるようにする。
- 自動制御と手動制御の状態を明確に区別する。
- 操作結果と実際に確認できた機器状態を区別して表示する。

## 5.2 画面一覧

| 画面 | パス | 主な機能 |
|---|---|---|
| ダッシュボード | `/` | 現在単価・制御状態・次回予定 |
| 電力予報 | `/forecast` | 今日・明日の料金グラフ |
| 運転スケジュール | `/schedule` | 自動生成された制御予定 |
| 制御履歴 | `/history` | 操作履歴・推定節約額 |
| 設定 | `/settings` | 制御条件・運用時間の変更 |

## 5.3 ダッシュボード

以下の情報を表示する。

**電力情報**

- 現在の電源料金単価
- 現在の推定実効単価
- 次の30分コマの料金
- 当日の最高・最低単価
- 予報の最終取得日時

**制御情報**

- 自動制御の有効・無効
- スマートプラグの現在状態
- 次回切り替え予定
- 最終操作結果
- システムの稼働状態

**集計情報**

- 本日の推定節約額
- 今月の推定節約額
- 本日の電源切り替え回数
- 本日のOFF累計時間

## 5.4 電力予報画面

Chart.jsで30分単位の料金推移を表示する。

- 今日・明日の切り替え表示
- 現在時刻の表示
- 料金単価の推移
- ON/OFF予定時間帯の可視化
- 最終取得日時
- データ取得エラーの表示

## 5.5 運転スケジュール画面

自動生成された制御予定を時系列で表示する。

| 時刻 | 予報単価 | 制御予定 |
|---|---:|---|
| 09:00 | 35円 | ON |
| 10:00 | 22円 | ON |
| 12:00 | 15円 | ON |
| 17:00 | 85円 | OFF |
| 18:00 | 60円 | ON |

※数値は表示例。

各予定には、制御理由と推定節約額を表示する。

## 5.6 制御履歴画面

以下を確認できるようにする。

- 操作日時
- 操作元（AUTO / MANUAL / SAFETY）
- 操作前状態
- 要求状態
- 操作後の確認結果
- 制御理由
- エラー情報

日付による絞り込みに対応する。

## 5.7 設定画面

初期リリースから制御条件をWeb UIで編集できるようにする。

主な設定項目：

| 設定 | 初期値 |
|---|---:|
| 運用開始時刻 | 09:00 |
| 運用終了時刻 | 18:00 |
| 最低節約単価差 | 20円/kWh |
| 充放電往復効率 | 85% |
| 最大連続OFF時間 | 120分 |
| 1日の最大OFF時間 | 180分 |
| 最低切り替え間隔 | 30分 |
| 想定平均負荷 | 150W |
| Dry Run | 有効 |

初期値はすべて仮設定とし、運用状況に応じて変更可能とする。

## 5.8 手動操作

ダッシュボードから以下を操作できるようにする。

1. 自動制御開始
2. 自動制御停止
3. スマートプラグON
4. スマートプラグOFF
5. スケジュール再生成
6. 料金予報の再取得

手動操作を行った場合はMANUALモードへ移行し、通常の自動制御が手動操作を上書きしないようにする。

安全制御はMANUALモード中も有効とする。

## 5.9 データ更新

HTMXによる定期的な部分更新を採用する。

| データ | 更新方式 |
|---|---|
| 現在単価 | 30～60秒ごとに表示更新 |
| プラグ状態 | 保存済み状態を定期表示 |
| 制御スケジュール | 計画更新時 |
| 推定節約額 | 定期更新 |
| 料金グラフ | 予報更新時 |
| システムエラー | 定期更新 |

画面更新のたびにSwitchBot APIを直接呼び出す構成は避ける。

## 5.10 セキュリティ

- 初期リリースでは宅内LANからのアクセスに限定する。
- インターネットへ直接公開しない。
- Web UIには認証を実装する。
- 状態変更リクエストにはCSRF対策を設ける。
- SwitchBotの認証情報はブラウザへ送信しない。
- 手動操作は履歴に記録する。
- 接続元の制限を適用できる構成とする。
