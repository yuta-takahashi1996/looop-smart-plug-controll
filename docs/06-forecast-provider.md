# Looopでんき予報取得設計

## 6.1 データソース

取得対象：

https://looop-denki.com/home/denkiforecast/

取得情報：

- 対象エリア：北海道
- 対象日時
- 30分ごとの電源料金単価
- 取得日時
- データソース

1日48コマの取得を基本とする。

でんき予報で公開されているのは電源料金単価のみで、請求単価（サービス料金・託送従量料金・再エネ賦課金・国の補助金などを含む1kWhあたりの単価）は取得できない。請求単価は §6.5 のとおり算出する。

## 6.2 取得方式

一般開発者向けの公式APIは公開されていない。でんき予報ページ（`/assets/js/modules/unit_price.js`）が利用している以下のエンドポイントから取得する（ログイン不要。2026年11月時点で確認）。

```text
GET https://looop-denki.com/api/prices?select_area=01
```

| エリアコード | エリア |
|---|---|
| 01 | 北海道 |
| 02〜09 | 東北・東京・中部・北陸・関西・中国・四国・九州 |
| 10 | 沖縄 |

レスポンス：

```json
{
  "0": {"price_data": [48コマ], "level": [...], "text": {...}, "yAxes_min": 0, "yAxes_max": 50},
  "1": {...},
  "2": {...},
  "label": [...],
  "timelist": ["0:00~0:29", ...]
}
```

- `0` / `1` / `2` はそれぞれ昨日・今日・明日。`price_data` が電源料金単価（円/kWh、税込）。
- `level` はでんき予報の区分で、制御スケジュールの生成に使う（docs/07-control-logic.md §7.4）。

| level | 区分 | 定義（平日。土日祝は過去3日間） |
|---|---|---|
| -0.5 | でんき日和 | 当日を除く過去5日間のJEPX平均値より5円以上低い単価のうち、最も低い10コマ |
| 0 | 区分なし | — |
| 0.5 | でんき注意報 | 当日を除く過去5日間のJEPX平均値より5円以上高い単価のうち、最も高い10コマ |
| 1 | でんき警報 | JEPX平均価格が100円を超える全コマ |

- 明日分が未公開のときは `disabled_flg`、データ欠損時は `defrect_flg` が付く。取得元のエラー時は `error` キーが返る。
- レスポンスに日付は含まれないため、取得時点の日本時間の日付から対象日を決める。日付境界での取り違えを防ぐため、0時の前後5分は取得しない。取得中に日付が変わった場合も結果を破棄する。
- サイトの規約類（`/policy/`、`/clause/`）に自動取得を禁止する記載は見当たらず、robots.txt の Disallow は `/api/image` のみ。取得は1日数回に留める。

料金取得部分はForecast Provider（`app/providers/looop.py`）として独立させる。仕様変更で取得できなくなった場合はProviderのみを差し替える。

## 6.3 取得タイミング

| タイミング | 処理 |
|---|---|
| システム起動時 | 当日予報取得 |
| 毎日16:15 | 翌日予報取得（でんき予報の明日分は16時頃に更新される） |
| 取得失敗時・未取得時 | 15分ごとに再取得（当日分、16:15以降は翌日分も） |
| Web UIからの操作 | 手動再取得 |

1回の取得では `FORECAST_RETRY_COUNT` 回まで再試行する。

システムが停止していた場合でも、次回起動時に当日予報を取得して動作する。

## 6.4 データ検証

- 対象エリアが一致していること
- 対象日が正しいこと
- 48コマが取得できていること
- 時刻が連続していること
- 単価が数値として取得できていること
- でんき予報の区分が48コマ分あり、すべて既知の値であること
- 重複・欠損がないこと
- データが有効期限内であること

過去日の料金データを当日の予報として流用しない。

検証に失敗した日のデータは保存せず、`system_events` にエラーとして記録する。同じコマを再取得した場合は最新の値で上書きする。

## 6.5 請求単価

請求単価は、実際の支払単価の目安として画面に表示するためだけに保持する。制御の判断・推定節約額には電源料金単価を用いる（docs/07-control-logic.md §7.1）。

```text
請求単価 = 電源料金単価（30分ごとに変動、でんき予報から取得）
         + 対象日に有効な加算額の合計（price_adjustments）
```

加算額は1kWhあたりの単価（税込）で、以下を登録する。

| 種類 | 内容 | 主な公開元 |
|---|---|---|
| サービス料金 | Looop のサービス料金単価 | 電気料金種別定義書（PDF） |
| 託送従量料金相当額 | エリアごとの託送従量料金 | 料金改定のお知らせ（画像） |
| 再エネ賦課金 | 国が年度ごとに定める | 資源エネルギー庁 |
| 補助金・値引き | 国の電気料金支援など（負の値） | お知らせ本文 |

- いずれも機械的に取得できる形で公開されていないため、適用期間（使用日ベース、終了日を含む）付きで設定画面から登録する。補助金のように期間が決まっているものは事前に登録できる。
- 基本料金・託送基本料金・容量拠出金相当額は kW 単位の月額のため、時間帯ごとの判断には含めない。
- DB には電源料金単価をそのまま保存し、請求単価は表示・計算のたびに算出する（加算額を修正したときに過去分も再計算されるようにするため）。
- 登録した加算額でアプリ表示の請求単価と一致するかは、同じコマの「アプリの請求単価 − でんき予報の電源料金単価」が登録した加算額と等しいことで確認する。
- スマホアプリの非公開APIは利用しない（利用規約・仕様変更・認証情報管理の観点）。

## 6.6 お知らせの検知

加算額の変更（料金改定・補助金）に気付けるよう、Looop のお知らせ一覧（`/home/news/`）を起動時と毎日1回確認する。タイトルが料金改定・託送・賦課金・料金支援・値引き等に該当する新着があれば、`system_events` に警告として記録し、ダッシュボードに表示する。加算額の値は自動更新しない（確定前の値や画像のみで公開される場合があるため）。初回の確認時に公開済みのお知らせは通知しない。
