# 18. ホストのメトリクス

本システムを動かしているホスト（本番は Raspberry Pi 5）の負荷を、Windows のタスクマネージャーの「パフォーマンス」のように画面でグラフ表示する。
SSH で htop を開かなくても、画面からホストの状態を確認できるようにするため。

## 18.1 方針

- **現在の状況の確認だけに使う。** 過去の推移は残さない。グラフには直近60秒を表示する。
- 値は**メモリにだけ**持ち、表示範囲（直近60秒）より古いものは順に捨てる。ストレージや DB には保存しない（SSD への書き込みを増やさない）。
- 制御の判断には使わない（表示専用）。取得に失敗しても制御には影響させない。

## 18.2 表示する項目

| 項目 | 値 | 取得元 |
|---|---|---|
| CPU 使用率 | 全体とコアごと（%） | `/proc/stat` の2回の差（iowait はアイドルに含める） |
| メモリ使用率 | 使用中・利用可能・合計（使用中＝合計 − `MemAvailable`。キャッシュなど解放できる分は使用中に含めない） | `/proc/meminfo` |
| ストレージの IO | 読み取り・書き込みの速度（バイト／秒）。物理ディスク全体の合計で、パーティション・loop・zram・ram・dm は除く | `/proc/diskstats`（`/sys/block` にあるディスク） |
| ストレージの容量 | 使用量・合計・使用率 | ルートファイルシステムの `statvfs` |
| ネットワークの IO | 受信・送信の速度。ビットレートで表示し、値に応じて bps・Kbps・Mbps・Gbps（1000 単位）にする。仮想のインターフェース（lo・docker・veth・br-・tailscale など）は除く | ホストの `/proc/1/net/dev` |
| CPU 温度 | ℃（取得できない環境では「—」） | `/sys/class/thermal/thermal_zone0/temp` |

## 18.3 取得の仕組み

- `app/services/host_metrics.py` の `HostMetricsCollector` が、専用のスレッドで **2秒ごと**に取得する（APScheduler のジョブにすると、実行のたびのログが増えるため使わない）。
  起動時に開始し、終了時に止める。`APP_ENV=test` では開始しない。
- 使用率・速度は前回の取得との差から求める。初回は差がないため、2回目から値が出る。カウンタが戻った場合は 0 とする。
- 読み取りに失敗しても例外を外に出さない。同じ失敗は続けて記録しない（2秒ごとにログが増えないように）。

### 18.3.1 Docker での取得

コンテナの中でも、CPU（`/proc/stat`）・メモリ（`/proc/meminfo`）・ディスクの IO（`/proc/diskstats`）・温度（`/sys`）はホストの値が読める。
ネットワークだけはコンテナ自身の値になるため、ホストの `/proc` を**読み取り専用**でマウントし（`/proc:/host/proc:ro`）、
`HOST_PROC_PATH=/host/proc` で指定する。ホストの PID 1 のネットワークの値（`/host/proc/1/net/dev`）がホスト全体の通信量になる。

- `network_mode: host` は使わない（同じ Compose の `mqtt` に名前で接続できなくなるため）。
- ストレージの容量は、コンテナのルート（overlay）の `statvfs` がホストのルートファイルシステムの値を返すため、マウントは不要。
- マウントしない場合（ローカルで直接起動するなど）は、そのホストの `/proc` を読む。`/proc/1/net/dev` が読めなければ `/proc/net/dev` を読む。

## 18.4 メトリクス画面（`/metrics`）

- ヘッダーのナビゲーションに「メトリクス」を追加する。ログインが必要。
- 左に項目の一覧（CPU・メモリ・ストレージ・ネットワーク・CPU 温度。それぞれ小さなグラフと現在値）、右に選んだ項目の詳細のグラフを表示する（タスクマネージャーと同じ形）。
  スマートフォンでは一覧を上に並べる。
- CPU の詳細には、コアごとの使用率のグラフを並べる。ストレージの詳細には、容量の使用率のバーを表示する。
- 画面は `GET /metrics/data?since=<UNIX 時刻>` を2秒ごとに取得し（`since` より新しい値だけ）、ブラウザのメモリでも直近60秒より古い値は捨てる。
  画面を開いた直後は、サーバーが持っている直近60秒の分をまとめて表示する。
- ブラウザのタブが見えていない間は取得しない。
- グラフは同梱の Chart.js を使う（`app/static/js/metrics.js`）。

## 18.5 ダッシュボードの概要

ダッシュボードに「ホストの状態」のカードを追加し、CPU・メモリ・CPU 温度・ストレージ・ネットワークの現在値と、メトリクス画面へのリンクを表示する。
ダッシュボードの部分更新（60秒ごと）と同じ間隔で更新する。起動直後で値がない場合は「メトリクスを取得中です」と表示する。
